# 前言    

如果你在工作中与容器打交道，那么或多或少都会用到 bitnami 的容器镜像或helm chart，在开源世界里更是有非常广泛的项目在使用 bitnami 的容器镜像或 helm chart，比如 karmada 的 helm chart 使用到了 bitnami 的 kubectl 这个 helm chart，比如使用 bitnami 的 etcd helm chart 来快速启动一个 etcd 集群。

bitnami 的容器镜像主要以安全、紧凑、合规等亮点来设计。每月超过5亿次容器镜像的下载(来自官网的介绍)，以及其发布的广泛容器镜像和持续创新能力在软件供应链安全领域脱颖而出。

# bitnami 容器镜像将不再更新

而在 2025年7月17日，bitnami 宣布从 2025年8月28日起 bitnami 将不再对容器镜像进行版本发布，主要的变更有以下几点：

- 会将现有的容器镜像迁移到 https://hub.docker.com/u/bitnamilegacy 中。
- 有一些容器镜像仍然会发布 latest 版本镜像到 https://hub.docker.com/u/bitnamisecure 用于开发使用。
- 容器镜像仓库 https://github.com/bitnami/containers 和 helm chart 仓库 https://github.com/bitnami/charts 仍然会更新，只是不会进行容器镜像版本发布。
- 2025年8月28日之后，https://hub.docker.com/u/bitnami 将只保留一组有限数量的容器镜像

如果希望继续使用 bitnami 容器镜像，可以考虑订阅 bitnami 安全容器镜像企业计划。

对于广大的用户群体来说，这是一个破坏性变更，主要是对原有容器镜像地址进行了更改/删除，因此如果你在线上环境直接使用了 bitnami 容器镜像，那么在 2025年8月28日之前你应该对相应的容器进行迁移，避免容器重启后由于无法拉取镜像从而程序奔溃。

# 使用以下命令进行一些迁移操作

找到 bitnami 容器镜像:
```shell
grep 'repository.*REPOSITORY_NAME/' postgresql/README.md | awk -F'\`' '{print $2, $(NF-1)}'
```

将现有的容器镜像地址更新为临时迁移使用的容器镜像地址:
```shell
helm upgrade RELEASE_NAME oci://registry-1.docker.io/bitnamicharts/CHART_NAME --version SAME_VERSION --set REPOSITORY_REFERENCE=bitnamilegacy
```

bitnami 公告 issue: [Upcoming changes to the Bitnami catalog (effective August 28th, 2025) ](https://github.com/bitnami/containers/issues/83267)

对于 helm chart 的一些讨论: [Clarification on bitnami/charts after August 28th](https://github.com/bitnami/charts/issues/35256)


# 写在最后

开源毫无疑问会造福大家，对于用户，你可以很轻易的获取到开源作者经过一番努力后产出的成果。但对于开源项目背后的商业公司来说这是一笔支出，因此对于这个决定我是能够理解的，并且提前一个月给出了通知从而让人们有了一定的缓冲时间。

而在这件事之前，刚好国内发生了一件相似的事件，那就是 kubesphere 将会闭源，并且在没有给出用户缓冲时间的条件下删除了项目文档和以往的容器镜像，因此这件事在国内/中文圈被热议讨论。与 kubespere 相比，bitnami 的做法相对来说要好很多，但即使是这样，bitnami 的这个决定也是诸多吐槽点。首先这个通知是发布在 bitnami 自己的仓库下，但绝大部分用户很可能不会注意到这么一个通知，因此这个通知是比较"小声"的。


无论如何，这对于社区来说是一个比较大的事情，如果你正在使用 bitnami 的容器镜像，那么是时候考虑迁移计划了！
